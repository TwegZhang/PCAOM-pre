# PCAOM V0 Documentation and Compiler Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有研究固化为可审查的 PCAOM 理论与 Compiler Contract V0，并以最小 reference compiler 验证“项目专属、最小充分、可解释”的主张。

**Architecture:** 理论、方法论、经验与 eval 同仓；Compiler 只读取项目输入并生成文档 artifact，不建立新的 Agent runtime。第一个编译目标是 Larry DSH Profile，采用稳定 Base Profile + 薄 Project Overlay；项目内每个需求以独立 Feature Spec 进入 DSH 执行循环。所有升级通过显式层级、单一 fan-out owner 和 evidence-driven recompile 控制。

**Tech Stack:** Markdown、YAML manifest、现有 Native Codex 能力；V0 不新增运行时依赖。

- [x] 将研究计划、研究 V1、理论路线统一为 foundations、related work、compiler model、escalation model、Superpowers/OMX study。

**Exit evidence:** 文档之间没有互相冲突的术语、层级或输出边界。

## Phase 4: Dogfood 与证据闭环

**Files:** `examples/`、`evals/`、`docs/research/`

- [ ] 选择一个真实但边界清晰的 repo，记录原始 Native/DIY baseline。
- [ ] 运行 Larry DSH 编译目标，比较强 Native Codex/OMX baseline、DSH-only 和 DSH + Codex escalation 的验证可靠性、Token/成本/延迟、人工干预和 artifact 复杂度。
- [ ] 记录失败、摩擦、重复控制和缺失控制；不要凭感觉新增规则。
- [ ] 将重复证据转成 recompile 建议，并保留 before/after。

**Exit evidence:** 至少一份可复查的 dogfood report，能说明新增控制是否值得其运行成本。

## Phase 5: V1 Explainability

- [ ] 增加输入 digest、版本、来源引用、成本估计和 escalation map。
- [ ] 增加 artifact diff 与“新增/修改/删除控制”的报告。
- [ ] 只有在 Phase 4 有证据时才扩展规则或升级逻辑。

**Exit evidence:** 人类可以从 manifest 和 rationale 重现一次生成决策，并识别应删除的控制。

## Phase 6: Evidence-Guided Recompiler（后续）

- [ ] 读取失败笔记、review finding、人工介入和 Token/延迟记录。
- [ ] 输出 add/modify/remove 建议，由人类批准后再生成新版本。
- [ ] 暂不引入自动 workflow search、数据库或长期服务。

**Exit evidence:** 同一类问题重复出现时，recompiler 能提出可解释的最小变更。

## 停止条件

在 Phase 4 以前不做自动优化、Web UI、多 Agent runtime 或新的 DSL。若 dogfood 不能证明项目特化 policy 比强 Native baseline 更有价值，应暂停扩展并修订理论或 Contract。
